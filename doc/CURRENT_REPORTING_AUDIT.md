# Current Reporting System Audit

## 1. Overview
The current Turnus reporting system is based on a **Markdown-first** approach. Reports are generated by converting internal data models (EMF EObjects) into Markdown strings, which are then optionally converted to HTML for display.

## 2. Architecture

### 2.1 Data Layer
*   **Source**: EMF (Eclipse Modeling Framework) EObjects.
*   **Examples**: `InterPartitionCommunicationAndMemoryReport`, `BottlenecksReport`.
*   These objects hold the raw analysis results (numbers, lists, graphs).

### 2.2 Export Logic
*   **Interface**: `turnus.common.io.FileExporter<T, U>`
    *   `T`: The input object type (e.g., the Report EObject).
    *   `U`: The content type (usually `StringBuffer` or `String`).
*   **Implementation Pattern**: `[AnalysisType]2[Format]Exporter`
    *   Example: `Ipcomm2MdExporter` (Inter-Partition Communication to Markdown).

### 2.3 Markdown Generation
*   **Method**: Manual String Concatenation.
*   **Class**: `Ipcomm2MdExporter` (and others).
*   **Process**:
    1.  The exporter iterates over the EMF object.
    2.  It appends Markdown syntax (`#`, `*`, `|`) to a `StringBuffer`.
    3.  Tables are built by manually aligning pipes `|` and dashes `-`.
    4.  Math is written as plain text or simple LaTeX-like strings.

### 2.4 HTML Generation
*   **Class**: `Ipcomm2HtmlExporter` (extends `Ipcomm2MdExporter`).
*   **Process**:
    1.  Calls `super.content(data)` to get the Markdown string.
    2.  Calls `turnus.model.utils.HtmlUtils.markdown2Html(mdString)`.
    3.  **Library**: Uses **CommonMark** (previously FlexMark) to parse MD and render HTML.
    4.  **Styling**: Injects `basic.css` and `basic.js` via `HtmlUtils.appendStyle/appendJs`.

## 3. Key Files

| Component | File Path | Description |
| :--- | :--- | :--- |
| **Base Interface** | `turnus.common.io.FileExporter` | Generic interface for all exporters. |
| **HTML Utility** | `turnus.model.utils.HtmlUtils` | Wraps CommonMark, handles CSS/JS injection. |
| **MD Exporter** | `.../io/Ipcomm2MdExporter.java` | Manually builds Markdown from data. |
| **HTML Exporter** | `.../io/Ipcomm2HtmlExporter.java` | Converts MD to HTML. |

## 4. Limitations of Current Approach

1.  **String Concatenation**: Building reports by appending strings is brittle and hard to test.
2.  **No Structured Output**: The "intermediate" format is Markdown text, not a structured data object (JSON). This makes it hard for other tools to consume the results.
3.  **Limited Visualization**: Charts are either static images or non-existent. Tables are basic HTML.
4.  **Coupling**: The logic for *what* to display is tightly coupled with *how* to display it (Markdown syntax).

## 5. Migration Context
This audit serves as the baseline for the migration to a **JSON + ECharts** approach. The goal is to replace the "Manual Markdown Construction" step with "Structured JSON Serialization".
